# 🎯 ВЕХА 3: Сетевая синхронизация, тактика и боевой фидбек (Задачи 11–15)
*Цель вехи:* Превратить локальный прототип в сетевой: настроить delta-синхронизацию состояний через Colyseus Schema, реализовать клиентскую интерполяцию и dead-reckoning, внедрить режим призрака, зоны баз и серверно-валидируемую боевую систему с визуальным фидбеком. Сервер выступает авторитетным арбитром урона и таймеров, клиент сохраняет аркадную отзывчивость.

---

### 🌐 Задача 11: Delta-синхронизация позиций (20 Гц)
**🎯 Цель:** Подключить Colyseus Schema для автоматической отправки только изменённых полей, настроить серверный тик-луп 20 Гц и клиентскую отправку `InputCommand` через `msgpack-lite`.

**🛠 Техническая реализация:**
- `shared/schemas/PlayerSchema.ts`:
  ```ts
  import { Schema, type } from '@colyseus/schema';
  export class PlayerSchema extends Schema {
    @type("number") x = 0; @type("number") y = 0;
    @type("number") vx = 0; @type("number") vy = 0;
    @type("number") hp = 100; @type("boolean") ghost = false;
    @type("number") ghostTimer = 0; @type("string") team = 'red';
  }
  ```
- `shared/schemas/RoomState.ts`: `@type({ map: PlayerSchema }) players = new MapSchema<PlayerSchema>();`
- `server/rooms/GameRoom.ts`: 
  ```ts
  setSimulationInterval(() => this.tick(), 50); // 20 Гц
  tick() { /* relay valid inputs, clamp bounds, update state */ }
  onCreate() { this.setState(new RoomState()); }
  onMessage(client, data) { /* parse msgpack, validate rate/bounds, apply */ }
  ```
- Клиент `NetworkManager.ts`: буферизует ввод, шлёт `room.send(new Uint8Array(msgpack.encode(input)))` строго 20 раз/сек.

**🏗 Архитектурный контекст:**  
Colyseus автоматически вычисляет дельту между тиками и шлёт только изменённые байты. `@colyseus/schema` берёт на себя бинарную сериализацию состояния, `msgpack-lite` упаковывает сырые команды. Сервер не симулирует физику, только валидирует границы и частоту ввода.

**✅ Результат / Как тестировать:**
- Открываем 2 вкладки → движение в одной мгновенно отображается во второй.
- `Colyseus Monitor` показывает комнату с 2 игроками, поля обновляются.
- Размер пакета состояния ≤80 байт/игрок (проверка через Wireshark/логгер).
- При 20+ командах/сек сервер логирует `Rate limit exceeded`, состояние не ломается.

### 📈 Задача 12: Интерполяция и предсказание (dead-reckoning)
**🎯 Цель:** Сгладить рывки при получении сетевых тиков, реализовать клиентское предсказание движения и плавную коррекцию дрифта >0.1px за 2 тика.

**🛠 Техническая реализация:**
- `utils/Interpolator.ts`: буфер `[{tick, x, y, vx, vy}]`. В `update(dt)` выбирает тики `N` и `N+1`, применяет `lerp = (serverTime - tickN_time) / tickDelta`.
- `utils/StatePredictor.ts`: локальный игрок сразу применяет ввод. При получении `StateSnapshot` считает `drift = hypot(local.x - server.x, local.y - server.y)`. Если `drift > 0.1` → запускает плавную коррекцию `position.lerp(serverPos, 0.5)` за 2 последующих кадра.
- Интеграция в `GameScene.update()`: `remotePlayer.setXY(interpolated.x, interpolated.y)`, `localPlayer` управляется предсказанием.

**🏗 Архитектурный контекст:**  
Клиент-авторитетность для локального игрока даёт мгновенный отклик (0 RTT задержки). Интерполяция для удалённых игроков скрывает сетевую задержку. Коррекция дрифта предотвращает «телепортации» без потери тактильности управления.

**✅ Результат / Как тестировать:**
- Имитация 50–80ms задержки (или реальный LAN) → движение противников плавное, без рывков.
- Резкая смена направления → дрифт корректируется незаметно, без «дёрганья» спрайта.
- FPS ≥60, память стабильна (буфер ограничен 2 тиками).

### 👻 Задача 13: Режим призрака и автоматический респавн
**🎯 Цель:** При `hp <= 0` перевести игрока в режим призрака (30 сек): полупрозрачность, отключение гравитации/коллизий, свободный полёт сквозь стены, авто-возврат на базу с полным HP.

**🛠 Техническая реализация:**
- Клиент `onDeath()`: 
  ```ts
  this.player.setTexture('player_ghost').setAlpha(0.4);
  this.player.body.setAllowGravity(false);
  this.player.body.setImmovable(true);
  this.player.setCollideWorldBounds(false);
  this.ghostTimer = 30;
  ```
- Сервер `onKill()`: `player.ghost = true; player.ghostTimer = 30;` → запускает таймер, каждую секунду декрементирует `ghostTimer`. При 0: `hp=100, ghost=false, spawnAtBase(team)`.
- Клиент отрисовывает таймер в HUD, отключает ввод стрельбы/подбора в этом режиме.

**🏗 Архитектурный контекст:**  
Режим поддерживает вовлечённость (разведка, наблюдение за боем) и исключает выпадение из сессии. Физика отключается намеренно: Arcade Physics не поддерживает «сквозные» коллизии без отключения `body.enable`.

**✅ Результат / Как тестировать:**
- Получение 100 урона → спрайт меняется на полупрозрачного призрака, гравитация отключается.
- Игрок летает сквозь стены/лут/других игроков, не получает урон, не может стрелять.
- Таймер в HUD тикает 30 → 0 → мгновенный респавн на базе, полное HP, нормальная физика.

### 🚩 Задача 14: Команды, зоны баз и пассивный урон
**🎯 Цель:** Закрепить команды Red/Blue, отрендерить зоны баз по всей высоте карты, реализовать пассивный урон 5 HP/сек при нахождении во вражеской зоне, настроить спавн на противоположных краях.

**🛠 Техническая реализация:**
- Лобби передаёт `team` → сервер сохраняет в `PlayerSchema.team`, клиент рисует оверлеи `base_red.png`/`base_blue.png` на краях (полная высота `mapHeight`).
- Клиент `update()`: если `player.team == 'blue' && player.x > enemyBaseLeftX` → запускает локальный таймер `5 HP/sec`, применяет `tint: 0xff4444`, `alpha`-моргане. Сервер в тик-лупе валидирует позицию и списывает HP.
- Спавн: `spawnX = (team === 'red') ? 100 : mapWidth - 100`, `spawnY = groundLevel`.

**🏗 Архитектурный контекст:**  
Механика борется с кемпингом, вынуждая игроков уходить в центр. Визуальная подсветка зон + моргание дают немедленный тактический фидбек. Серверный валидатор предотвращает клиентский спам HP.

**✅ Результат / Как тестировать:**
- Синий игрок заходит на правый край → HP тикает вниз, экран/спрайт мигает красным.
- Таймер урона стабильный (5 HP/сек ±0.2), при выходе из зоны урон останавливается.
- Респавн всегда происходит на своём краю карты, даже после смерти в зоне врага.

### 💥 Задача 15: Обработка попаданий и визуальный фидбек
**🎯 Цель:** Реализовать клиентский `overlap` снарядов с врагами, серверную валидацию `hit`, нанесение урона, отключение дружественного огня и визуальный фидбек (красный tint/моргане, смена спрайта при повреждении).

**🛠 Техническая реализация:**
- Клиент `overlap(proj, enemy)`: если `enemy.team != player.team` → шлёт `HitEvent(targetId, proj.x, proj.y)` серверу. Временно отключает повторный overlap для этого снаряда.
- Сервер `onMessage('hit', data)`: проверяет дистанцию, команду, частоту. Если валидно → `target.hp -= damage`, если `hp<=0` → `kill`. Рассылает `EventPayload({type:'hit', targetId, hp})`.
- Клиент `onEvent('hit')`: применяет `player_damage.png` или `tint: 0xff0000`, `alpha`-пульсация 0.3с, обновляет HUD. Дружественные попадания игнорируются полностью (нет события, нет урона).

**🏗 Архитектурный контекст:**  
Клиент отвечает за мгновенный визуальный отклик (feel), сервер — за целостность состояния (anti-cheat). Разделение урона и физического откидывания (взрывы) реализовано намеренно: spec требует отключить дружественный урон, но сохранить физику взрывов для всех.

**✅ Результат / Как тестировать:**
- Попадание во врага → красная вспышка, HP уменьшается, при 0 → переход в призрака.
- Попадание в союзника → никакого урона, никаких сетевых событий, снаряд просто проходит.
- HUD обновляется мгновенно, чужие HP не отображаются (только свои и союзников).
- Сервер логирует `Hit validated`, `Damage applied`, `Kill registered`.
