# 🎯 ВЕХА 4: Боевая глубина, лут-цикл и процедурные карты (Задачи 16–20)
*Цель вехи:* Превратить базовый шутер в тактическую аркаду: добавить взрывы с универсальным откидыванием, полноценную систему HP/смерти с сохранением тел, механику осознанного подбора оружия в приседе, переход на кулаки при истощении боезапаса и процедурную генерацию проходимых карт с ограниченным FOV. Каждый шаг даёт ощутимый геймплейный сдвиг и готов к демонстрации.

### 💣 Задача 16: Взрывы и физика откидывания
**🎯 Цель:** Реализовать взрыв гранат/РПГ при контакте, мгновенный визуальный фидбек, откидывание всех игроков в радиусе (включая союзников) и нанесение урона только противникам.

**🛠 Техническая реализация:**
- Клиент `Projectile.ts` при `overlap` с тайлом/игроком:
  ```ts
  this.scene.events.emit('explosion', { x: this.x, y: this.y, weapon: this.weaponType });
  this.setActive(false).setVisible(false);
  ```
- Сервер `GameRoom.onMessage('explode')`: валидирует дистанцию/тип/ammo/частоту → шлёт `EventPayload({type:'explode', x, y, radius, ownerId})`.
- Клиент `ExplosionSystem.ts`:
  ```ts
  // Формула из спеки: force = (1 - dist/radius) * maxKnockback
  const dist = Phaser.Math.Distance.Between(player.x, player.y, explodeX, explodeY);
  if (dist < radius) {
    const force = (1 - dist / radius) * PHYSICS.MAX_KNOCKBACK;
    const angle = Phaser.Math.Angle.Between(explodeX, explodeY, player.x, player.y);
    player.body.setVelocity(Math.cos(angle) * force, Math.sin(angle) * force);
  }
  // Визуал: explosion_01.png, таймер 0.3с → setActive(false)
  ```
- Урон рассчитывается сервером: если `player.team !== ownerId.team` → `hp -= damage`.

**🏗 Архитектурный контекст:**  
Откидывание считается на клиенте для мгновенного отклика (0 RTT), урон валидируется на сервере. Это разделение сохраняет аркадность, но защищает от спуфинга. Союзники летят, но не теряют HP (тактическая механика из спеки).

**✅ Результат / Как тестировать:**
- Выстрел гранатой/РПГ → вспышка `explosion_01`, все в радиусе отлетают.
- Сила отброса плавно уменьшается от центра к краю радиуса.
- Союзники откидываются без потери HP, противники теряют HP.
- Визуал исчезает через 0.3с, пул объектов переиспользуется, FPS ≥60.

### ❤️ Задача 17: Полный цикл HP, смерть и пассивный урон в зоне
**🎯 Цель:** Довести систему здоровья до продакшен-качества: скрытие HP от врагов, пассивный урон 5 HP/сек в зоне противника, фиксация смерти при 100 урона, отрисовка тела на 10 сек, корректный переход в призрака.

**🛠 Техническая реализация:**
- Клиент `HUDSystem.ts`: рендер шкалы HP. Видна только если `target.team === localPlayer.team || target.id === localPlayer.id`.
- Зона урона: серверный тик проверяет `player.x` относительно базовых границ. Если во вражеской зоне → `player.hp -= 1` каждые 200мс (5/сек). Рассылает `EventPayload({type:'zone_damage', targetId})`.
- Клиент при получении урона: `tint: 0xff4444`, `alpha` пульсация 0.3с, переключение на `player_damage.png`.
- Смерть: `hp <= 0` → сервер логирует `kill` или `environment_death`, шлёт `respawn` событие. Клиент спавнит `dead_body.png` на месте смерти, таймер 10с → `setActive(false)`. Мгновенный переход в `ghost` режим (интеграция с Задачей 13).

**🏗 Архитектурный контекст:**  
Скрытый HP у врагов создаёт психологическое давление и блеф. Пассивный урон вычисляется на сервере в тик-лупе, чтобы исключить клиентский фальсификат. Тела как маркеры боя повышают читаемость карты без UI-шума.

**✅ Результат / Как тестировать:**
- HP бар виден себе и союзникам, скрыт у врагов.
- Вход во вражескую зону → моргание красным, HP тикает вниз ровно 5/сек.
- При 0 HP → спавн тела (10 сек), переход в призрака, счёт обновляется.
- Смерть от зоны начисляет очко противоположной команде (лог сервера подтверждает).

### 🎒 Задача 18: Подбор оружия в приседе
**🎯 Цель:** Реализовать тактический подбор: только в приседе, замена текущего оружия, выпадение старого на ту же позицию с остатком патронов, блокировка бесконечной смены в одном приседе.

**🛠 Техническая реализация:**
- Клиент `GameScene.update()`:
  ```ts
  if (this.keys.CROUCH.isDown && this.pickupCooldown <= 0) {
    const pickup = this.physics.overlap(this.player, this.weaponGroup).pop();
    if (pickup) {
      this.room.send('pickup', { pickupId: pickup.id, weaponId: pickup.weaponType });
      this.pickupCooldown = 300; // серверный кулдаун
    }
  }
  this.pickupCooldown -= dt;
  ```
- Сервер `onMessage('pickup')`: проверяет `player.crouch == true`, `pickupCooldown <= 0`. Если ок:
  1. Сохраняет текущее оружие игрока как `dropped_weapon` на координатах спавна.
  2. Меняет `player.weapon`, сбрасывает `pickupCooldown`.
  3. Рассылает `EventPayload({type:'swap', playerId, newWeapon, oldWeaponDropPos})`.
- Клиент применяет обмен, спавнит лут-объект по координатам, обновляет HUD.

**🏗 Архитектурный контекст:**  
Механика заставляет игрока останавливаться и рисковать, ломая run-and-gun стиль. Серверный кулдаун предотвращает макросы и спам, но главное правило из концепта — один подбор за одно удержание приседа. Поэтому сервер хранит флаг `pickedDuringCurrentCrouch` и сбрасывает его только когда игрок полностью отпустил присед. Выпадающее оружие с остатком патронов создаёт динамические точки интереса.

**✅ Результат / Как тестировать:**
- Подбор возможен только при зажатом `Ctrl`.
- После обмена старый пушка падает на пол с текущим количеством патронов.
- Блокировка повторного подбора, пока игрок не встанет: одного 300ms cooldown недостаточно, иначе можно держать присед и циклически менять оружие.
- Синхронизация обмена видна всем игрокам без рассинхрона.

### 👊 Задача 19: Расход патронов и переход на кулаки
**🎯 Цель:** Реализовать пул патронов без перезарядки, мгновенное удаление оружия при `ammo=0`, активацию кулаков (10 урона, ∞, без откидывания), сохранение кликового формата стрельбы.

**🛠 Техническая реализация:**
- Клиент `WeaponSystem.ts`: `player.ammo--` при каждом успешном выстреле/взрыве.
- При `ammo <= 0`:
  ```ts
  this.player.weapon = 'fist';
  this.player.damage = 10;
  this.player.knockbackMultiplier = 0; // кулаки не откидывают
  this.updateWeaponHUD('fist', '∞');
  // Удаляем визуал оружия с рук
  ```
- Кулаки: при `input.click` проверяется `overlap` в радиусе 40px. Если есть враг → `room.send('hit', {targetId, damage: 10})`. Нет снаряда, нет анимации полёта.
- Сервер валидирует `ammo` перед каждым выстрелом. При расхождении → принудительный свич на `fist`.

**🏗 Архитектурный контекст:**  
Отсутствие перезарядки сохраняет высокий темп. Кулаки как fallback гарантируют, что игрок никогда не выпадает из боя. Формат "клик = выстрел/удар" унифицирует ввод и упрощает баланс.

**✅ Результат / Как тестировать:**
- Отстрел пистолета до 0 → оружие исчезает, HUD показывает кулаки, патроны `∞`.
- Клик по врагу в ближнем бою → 10 урона, противник не отлетает.
- Подбор нового оружия мгновенно возвращает пушку и счётчик патронов.
- Сервер логирует корректный расход и переход состояний.

### 🗺 Задача 20: Процедурная генерация карты и зум камеры
**🎯 Цель:** Реализовать seed-based генерацию линейных катакомб, гарантировать проходимость (перепад ≤ 2×прыжок), закрыть пол от провалов, настроить камеру `zoom=1.8` с deadzone.

**🛠 Техническая реализация:**
- Сервер `MapGenerator.ts`: создаёт `seed` → рассылает `MapSeed` пакет при старте раунда.
- Клиент `MapBuilder.ts` (запуск по `MapSeed`):
  ```ts
  const rng = new Mulberry32(seed);
  // Генерация сетки тайлов: floor, wall, ramp
  // Валидация: flood-fill от spawnLeft до spawnRight
  // Проверка: verticalGap <= jumpHeight * 2 (≈ 900px)
  this.buildMapFromTiles(tiles);
  this.camera.setZoom(1.8);
  this.camera.setDeadzone(200, 150);
  this.camera.setBounds(0, 0, mapWidth, mapHeight);
  ```
- Физика: `setImmovable(true)` для стен. Рампы в Arcade Physics не имеют штатного `setSlope()`, поэтому в MVP наклоны либо визуальные, либо заменены ступенями/прямоугольными коллайдерами. Пол всегда заполнен, дыры исключены алгоритмически.
- Все спавны оружия расставляются валидными узлами (проверка `walkable`).

**🏗 Архитектурный контекст:**  
Детерминированная генерация по seed гарантирует идентичность карты у всех клиентов при нулевой передаче сетевых данных (только 8-байтный seed). Ограничение FOV зумом добавляет тактическую неизвестность без "тумана войны". Гарантия проходимости критична для LAN-баланса.

**✅ Результат / Как тестировать:**
- Рестарт/смена seed → уникальная карта, генерация <1 сек.
- Игрок может пройти от левой до правой базы без застреваний.
- Нет провалов, перепады высот преодолимы двойным прыжком.
- Камера приближена, дальние углы скрыты, deadzone работает плавно.
- Все игроки видят идентичную геометрию и тайлы.
