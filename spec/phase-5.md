# 🎯 ВЕХА 5: Игровой цикл, статистика и администрирование (Задачи 21–25)
*Цель вехи:* Завершить системный каркас матча: зафиксировать ограничение обзора камерой, реализовать строгий цикл фаз (Лобби → Бой → Пауза → Рестарт), внедрить серверно-авторитетный подсчёт очков с учётом суицидов, отрисовать таблицу статистики по КПД и добавить защищённую панель админа с автобалансом. Каждая задача даёт законченный UI/UX или системный блок, готовый к демонстрации.

### 🔍 Задача 21: Зум камеры и ограничение FOV
**🎯 Цель:** Довести камеру до спеки: `zoom=1.1`, `deadzone`, плавное следование, строгие границы карты. Обеспечить тактическую неизвестность без тумана/масок.

**🛠 Техническая реализация:**
- В `CameraController.ts` (вызывается после генерации карты):
  ```ts
  this.cameras.main.setZoom(1.1);
  this.cameras.main.setDeadzone(200, 150);
  this.cameras.main.startFollow(player, true, 0.1, 0.1);
  this.cameras.main.setBounds(0, 0, mapWidth, mapHeight);
  // Отключаем world wrap, фиксируем viewport
  this.cameras.main.setBackgroundColor('#1a1a1a');
  ```
- При ресайзе окна: пересчёт `setBounds` с учётом `window.innerWidth / zoom`.
- Интеграция с `GameScene`: камера инициализируется только после получения `MapSeed` и построения тайлов.

**🏗 Архитектурный контекст:**  
Spec требует ограничивать FOV именно зумом, а не overlay-масками. `deadzone` предотвращает дёрганье камеры при микро-движениях. Границы камеры синхронизированы с процедурной картой, чтобы клиент не рендерил пустоту за пределами мира.

**✅ Результат / Как тестировать:**
- Камера приближена, видна только локальная область карты.
- Движение игрока → камера плавно следует, но не сдвигается в `deadzone`.
- Край карты чётко виден, за пределами чёрный фон/нет рендера.
- Работает при любом разрешении окна, zoom сохраняется стабильно.

### ⏱ Задача 22: Игровой цикл и фазы матча
**🎯 Цель:** Реализовать строгий таймер и переходы фаз: `Lobby (свободно) → Fight (10 мин) → Pause (1 мин) → Restart (мгновенно)`.

**🛠 Техническая реализация:**
- Сервер `MatchCycle.ts`:
  ```ts
  enum Phase { LOBBY, FIGHT, PAUSE }
  let phase = Phase.LOBBY;
  let timer = 600;
  setInterval(() => {
    if (phase === Phase.LOBBY) return;
    timer -= 1;
    if (phase === Phase.FIGHT && timer <= 0) { phase = Phase.PAUSE; timer = 60; broadcast('phase_change', PAUSE); }
    else if (phase === Phase.PAUSE && timer <= 0) { resetState(); phase = Phase.FIGHT; timer = 600; broadcast('phase_change', FIGHT); }
  }, 1000);
  ```
- Клиент слушает `EventPayload({type:'phase_change'})`:
  - `LOBBY` → HUD показывает "Ожидание игроков", разрешён join.
  - `FIGHT` → запускается визуальный таймер, блокируется вход новых (опционально, спека не запрещает, но для баланса рекомендуется).
  - `PAUSE` → заморозка ввода, отрисовка оверлея статистики.
  - `RESTART` → мгновенная очистка `Projectile/WeaponGroup`, респавн игроков, новый `MapSeed`.

**🏗 Архитектурный контекст:**  
Сервер является единственным источником правды для фаз. Клиент только реагирует. Цикл жёстко привязан к системному таймеру сервера, что исключает рассинхрон между клиентами. ResetState обнуляет всё, кроме ников и подключений.

**✅ Результат / Как тестировать:**
- Матч стартует → таймер 10:00 тикает вниз.
- 0:00 → автоматический переход в паузу, ввод заблокирован.
- 1:00 паузы → автоматический рестарт, новая карта, счёт сброшен, игроки на спавнах.
- Фазы синхронизированы у всех подключённых клиентов ±1 тик.

### 🏆 Задача 23: Подсчёт очков и условие победы
**🎯 Цель:** Внедрить серверно-авторитетную систему очков: `+1` за килл, `+1` противнику за суицид/смерть от среды, фиксация победы по итогу 10 минут.

**🛠 Техническая реализация:**
- Сервер `StatTracker.ts`:
  ```ts
  // При kill
  attacker.team.score += 1;
  attacker.stats.kills += 1;
  victim.stats.deaths += 1;
  
  // При environment_death (зона, падение и т.д.)
  const lastAttacker = victim.lastDamageSourceId;
  if (lastAttacker) {
    getPlayer(lastAttacker).team.score += 1;
    getPlayer(lastAttacker).stats.kills += 1;
  } else {
    // Чистый суицид → +1 команде противника (берём любую, если врагов нет, иначе по балансу)
    getOppositeTeam(victim.team).score += 1;
  }
  victim.stats.deaths += 1;
  ```
- При `phase_change(PAUSE)`: сервер сравнивает `red.score` vs `blue.score`, формирует `StatsPacket`, рассылает всем.
- Клиент отображает победителя в HUD: `"ПОБЕДА: КРАСНЫЕ | 14 : 9"`.

**🏗 Архитектурный контекст:**  
Spec чётко разделяет киллы и смерти от среды. Хранение `lastDamageSourceId` (обновляется при любом `hit`/`zone_damage`) позволяет корректно атрибутировать очки. Серверная валидация исключает клиентский спуфинг счёта.

**✅ Результат / Как тестировать:**
- Убийство врага → счёт команды +1, личная статистика обновляется.
- Смерть от зоны → +1 команде противника, последний атакующий получает +1 к киллам.
- Конец матча → система корректно определяет победителя, счёт блокируется до рестарта.

### 📊 Задача 24: Таблица статистики и подсветка
**🎯 Цель:** Отрисовать пост-матчевую таблицу: ники, убийства, смерти, КПД (`убийств - смертей`), сортировка по КПД, подсветка локального игрока, итоговый счёт команд.

**🛠 Техническая реализация:**
- Клиент `StatsOverlay.ts` (DOM-элемент поверх Phaser):
  ```html
  <table id="stats-table">
    <tr><th>Ник</th><th>Убийства</th><th>Смерти</th><th>КПД</th></tr>
    <!-- JS генерирует строки -->
  </table>
  ```
- JS-логика при получении `StatsPacket`:
  ```ts
  const rows = players.map(p => ({...p, kdr: p.kills - p.deaths}));
  rows.sort((a, b) => b.kdr - a.kdr);
  // Рендер строк, поиск localPlayer.uuid → добавление класса .highlight
  document.getElementById('local-row').classList.add('highlight');
  ```
- Стили: `tr.highlight { background: rgba(255,215,0,0.25); font-weight: bold; }`. Адаптивная вёрстка, скролл при >20 игроков.

**🏗 Архитектурный контекст:**  
Таблица полностью клиентская, рендерится на основе финального снапшота от сервера. КПД считается как разность, а не коэффициент (по спеке). Подсветка через CSS-класс надёжнее, чем поиск по DOM в рантайме Phaser.

**✅ Результат / Как тестировать:**
- Таблица открывается в фазе паузы.
- Строки отсортированы по убыванию `(kills - deaths)`.
- Строка текущего игрока выделена цветом/жирным шрифтом.
- Данные совпадают с логикой задачи 23, итоговый счёт команд виден сверху.

### 🛡 Задача 25: Админ-команды и автобаланс
**🎯 Цель:** Реализовать парольную админ-панель: кнопки `Пересоздать`, `Автобаланс`, контроль разницы в командах, логирование действий в чат.

**🛠 Техническая реализация:**
- Клиент `AdminPanel.ts`: скрыт по умолчанию. Открывается по `/admin` или хоткею `~`. Ввод пароля → `room.send('admin_auth', { password })`.
- Сервер `AdminController.ts`:
  ```ts
  const ADMIN_PASS_HASH = '...'; // простое сравнение или хеш
  onMessage('admin_auth', (client, data) => {
    if (validatePass(data.password)) { client.isAdmin = true; broadcast('admin_granted', client.id); }
  });
  onMessage('admin_cmd', (client, data) => {
    if (!client.isAdmin) return;
    if (data.type === 'restart') triggerRestart();
    if (data.type === 'toggle_balance') autoBalanceEnabled = !autoBalanceEnabled;
  });
  // Автобаланс при onJoin:
  onJoin(client) {
    if (autoBalanceEnabled && Math.abs(redCount - blueCount) > 1) {
      assignToSmallerTeam(client);
    }
  }
  ```
- Клиент рендерит UI только для `isAdmin=true`, кнопки вызывают `AdminCommand`. Все действия логируются в системный чат: `"[ADMIN] Match restarted by Nick"`.

**🏗 Архитектурный контекст:**  
Spec требует, чтобы любой знающий пароль мог управлять сессией. Валидация строго на сервере. Автобаланс работает в реальном времени, ограничивая разницу в 1-2 игрока. Админ-команды редкие, поэтому их не нужно оптимизировать раньше боевого трафика.

**✅ Результат / Как тестировать:**
- Ввод верного пароля → появляются кнопки админа.
- `Пересоздать` → мгновенный рестарт матча, лог в чат.
- `Автобаланс` → входящие игроки распределяются поровну, ручная смена команды блокируется при превышении лимита.
- Ошибочный пароль → UI остаётся скрыт, сервер логирует `auth_failed`.
