*Цель вехи:* Собрать все системы в единый, стабильный и оптимизированный продукт. Реализовать финальный HUD и системный чат, жёстко ограничить сетевой трафик, внедрить пулинг и отсечение для стабильных 60 FPS на слабом железе, добавить отладочный режим с эмуляцией потерь сети и подготовить продакшен-сборку, запускаемую одной командой. Каждая задача закрывает критичный для сдачи проекта блок.

### 📟 Задача 26: Финальный HUD, таймер матча и системный чат
**🎯 Цель:** Реализовать компактный, не перекрывающий обзор интерфейс: шкала HP, оружие/патроны, командный счёт, таймер матча и ленту системных событий внизу экрана.

**🛠 Техническая реализация:**
- Клиент `HudSystem.ts` (DOM-оверлей поверх `canvas`):
  ```html
  <div id="hud">
    <div class="top-bar">
      <span id="score">🔴 12 : 9 🔵</span>
      <span id="timer">08:42</span>
    </div>
    <div class="bottom-left" id="weapon-info">🔫 Пистолет [34]</div>
    <div class="bottom-right" id="hp-bar" style="width: 100%; background: linear-gradient(to right, #ff4444 0%, #ff4444 100%);"></div>
    <div id="system-chat" class="chat-log"></div>
  </div>
  ```
- JS-логика: подписка на `room.state` и `EventPayload`. Таймер обновляется каждую секунду от сервера. Чат принимает события: `player joined`, `phase: FIGHT`, `restart`, `admin balance toggled`. Автоскролл, хранение последних 20 строк.
- CSS: `pointer-events: none` на оверлеях, `user-select: none`, адаптив под `1280x720` и `window resize`.

**🏗 Архитектурный контекст:**  
DOM-оверлей выбран вместо Phaser UI для лучшей производительности текста и простоты стилизации. Чат работает асинхронно: логи пишутся, но не блокируют `requestAnimationFrame`. Скрытый HP у врагов реализован через фильтрацию событий на клиенте.

**✅ Результат / Как тестировать:**
- Все блоки обновляются в реальном времени, не перекрывают игровую область.
- Системный чат пишет события без паузы геймплея, автоскролл плавный.
- При ресайзе окна элементы масштабируются или центрируются без наложения.
- HP-бар скрывается у врагов, виден только себе и союзникам.

### 📉 Задача 27: Оптимизация сети, троттлинг и контроль размера пакетов
**🎯 Цель:** Жёстко ограничить трафик: клиент шлёт ≤20 команд/сек, сервер дропает лишнее, итоговый пакет ≤150 байт/тик/игрок. Интеграция `msgpack-lite` и логирование размеров.

**🛠 Техническая реализация:**
- Клиент `InputBuffer.ts`: накапливает изменения, отправляет строго каждые 50ms через `room.send(msgpack.pack(input))`. Если состояние не изменилось → пропускает тик.
- Сервер `RateLimiter.ts`:
  ```ts
  const TICK_WINDOW = 50; // ms
  const MAX_TICKS = 1;
  let lastTick = 0;
  onMessage(client, data) {
    const now = Date.now();
    if (now - lastTick < TICK_WINDOW) return; // дроп
    lastTick = now;
    processInput(client, msgpack.unpack(data));
  }
  ```
- `PacketLogger.ts` (dev-only): измеряет `Buffer.byteLength(serialized)`, логирует `WARN: Packet > 150B`.
- Colyseus Schema уже обеспечивает delta-encoding. Ограничение `@type` до `number`/`boolean` минимизирует оверхед.

**🏗 Архитектурный контекст:**  
Spec требует ≤150 байт/тик и 20 Гц. Сервер не буферизует дропнутые команды (анти-спам). Клиентский троттлинг гарантирует стабильный апстрим. `msgpack-lite` даёт ~40% сжатия против JSON без потери типов.

**✅ Результат / Как тестировать:**
- Логгер показывает стабильный размер пакетов: `112–138 байт/тик`.
- При нажатии 50 кнопок/сек сервер обрабатывает только 20, остальные молча дропаются.
- При 10 игроках общий трафик ≤30 КБ/с, сервер CPU <15%.
- Wireshark/лог подтверждает отсутствие JSON в продакшн-трафике.

### 🔄 Задача 28: Пулинг объектов и рендер-отсечение
**🎯 Цель:** Исключить GC-фризы и просадки FPS при интенсивном бою через `Phaser.Group` с `maxSize:50`, переиспользование снарядов/взрывов/лута/тел и отсечение off-screen объектов.

**🛠 Техническая реализация:**
- `client/entities/PoolManager.ts`:
  ```ts
  this.projectiles = this.physics.add.group({ maxSize: 50, classType: Projectile, runChildUpdate: true });
  this.explosions = this.add.group({ maxSize: 50, classType: Explosion });
  this.bodies = this.add.group({ maxSize: 20, classType: DeadBody });
  ```
- При спавне: `pool.get()` → `setActive(true).setPosition(...)` → запуск таймера/физики.
- В `update()`: `if (!camera.intersects(sprite.getBounds())) sprite.setActive(false);`
- При уничтожении: `sprite.setActive(false).setVisible(false).setVelocity(0)` → возврат в пул.
- Отключение `setActive(false)` останавливает `update()` и рендер объекта.

**🏗 Архитектурный контекст:**  
Создание/удаление `new Sprite()` в JS-рантайме вызывает частые сборки мусора. Пулинг фиксирует память заранее. `setActive(false)` полностью выводит объект из цикла обновления Phaser, что критично для слабых клиентов (i3/4GB).

**✅ Результат / Как тестировать:**
- Интенсивный бой (50+ выстрелов, 5 взрывов, 3 лута) → FPS держится ≥60, нет микрофризов.
- Профилировщик браузера показывает плоскую линию `Heap Used`, нулевые GC-паузы >5ms.
- Объекты за пределами камеры не потребляют CPU/GPU, мгновенно реактивируются при входе в FOV.

### 🛠 Задача 29: Отладочный режим и эмуляция сетевых потерь
**🎯 Цель:** Включить визуализацию хитбоксов/физики, логирование тик-рейта/дрифта/потерь пакетов и предоставить скрипт эмуляции задержки/потерь для тестов на слабой сети.

**🛠 Техническая реализация:**
- Переключатель `config.debug = process.env.DEBUG === 'true'`.
- В `GameScene.create()`: `this.physics.world.drawDebug = true;` → отрисовка AABB, векторов скорости, радиусов взрывов.
- `DebugOverlay.ts`: рендерит поверх HUD: `FPS: 60 | RTT: 12ms | Drift: 0.04px | Packets/s: 19/20 | Loss: 0%`.
- Скрипт `scripts/emulate-lag.sh`:
  ```bash
  sudo tc qdisc add dev lo root netem delay 50ms loss 1% duplicate 0.5%
  # Отключение: sudo tc qdisc del dev lo root
  ```
- Валидация: при включении эмуляции интерполяция сглаживает рывки, dead-reckoning корректно предсказывает, дрифт гасится за 2 тика.

**🏗 Архитектурный контекст:**  
Отладочный режим отключается в продакшене через `.env`. Визуализация физики помогает QA проверять коллизии и радиусы. Эмуляция `tc` имитирует реальные LAN-потери без замены роутера, подтверждая устойчивость сетевого слоя.

**✅ Результат / Как тестировать:**
- `DEBUG=true npm run dev` → видны хитбоксы, векторы, сетевая статистика.
- Запуск `emulate-lag.sh` → задержка 50ms, потери 1% → игра не рвётся, интерполяция держит плавность.
- Выключение debug → оверлеи и отрисовка физики полностью отключены, FPS возвращается к базовому.

**🛠 Техническая реализация:**
- `package.json` скрипты:
  ```json
  "build": "npm run build:shared && vite build --config client/vite.config.ts && tsc -p server/tsconfig.json",
  "start": "node server/dist/index.js"
  ```
