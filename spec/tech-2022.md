## 2. АРХИТЕКТУРА И РАЗДЕЛЕНИЕ ОТВЕТСТВЕННОСТИ

### 🔹 Принцип: **Client-Authoritative Gameplay + Server-Relay & Validator**
| Слой | Что вычисляет | Что валидирует | Что отправляет в сеть |
|------|---------------|----------------|------------------------|
| **Клиент** | Ввод, движение, двойной прыжок, присед, подбор оружия (визуально), стрельба, полёт снарядов, взрывы, knockback, рендер, камера, HUD, интерполяция, dead-reckoning | Локальные лимиты (частота кликов, прыжков, приседа) | `InputCommand` (движение, прыжок, присед, клик, подбор), `ClientState` (позиция, состояние) |
| **Сервер** | Тик-луп (20 Гц), генерация seed, статистика, распределение спавнов оружия, таймер матча, админ-логика, автобаланс | Границы карты, `kill`/`death`, `pickup` (anti-spam), частота команд, целостность seed, коррекция дрифта | `StateSnapshot` (delta), `EventPayload` (hit, explosion, respawn, admin), `MapSeed` |

### 🔹 Сетевой цикл
```
Серверный тик: 20 Гц (фиксированный шаг, 50ms)
Клиентская отправка: 20 Гц (только при изменении состояния или по таймеру)
Интерполяция: Клиент буферизует 2 последних тика состояния других игроков. 
              Применяет линейную интерполяцию между тиками N и N+1.
Предсказание (Prediction): Клиент сразу применяет ввод к локальному игроку. 
                           При получении подтверждения от сервера проверяет рассинхрон. 
                           Если |drift| > 0.1px → плавная коррекция за 2 тика.
Снапшот-коррекция: Каждые 3 секунды сервер шлёт полный StateSnapshot. 
                   Клиент синхронизирует позиции, HP, оружие, состояние призрака.
```

## 4. СЕТЕВОЙ КОНТРАКТ И ОПТИМИЗАЦИЯ

### 🔹 Пакеты (MsgPack / Colyseus Schema)
| Тип | Направление | Содержание | Частота | Размер (цель) |
|-----|-------------|------------|---------|---------------|
| `MapSeed` | Server → Client | `seed: number`, `mapWidth: number`, `mapHeight: number` | 1 раз при старте | ~8 байт |
| `InputCommand` | Client → Server | `move: -1\|0\|1`, `jump: bool`, `crouch: bool`, `click: bool`, `pickup: bool`, `tick: number` | 20 Гц (только при изменении) | ~12 байт |
| `StateSnapshot` | Server → Client (Delta) | `players: [{id, x, y, vx, vy, hp, state, weapon, ghostTimer}]`, `matchTime` | 20 Гц | ~40-80 байт/игрок |
| `EventPayload` | Server → Client | `type: 'hit'\|'explode'\|'respawn'\|'death'\|'admin'`, ` {...}` | По событию | ~20-60 байт |
| `AdminCommand` | Client → Server | `type: 'restart'\|'balance_toggle'`, `password: string` | Редко | ~16 байт |

### 🔹 Оптимизационные правила
1. **Дельта-синхронизация:** Использовать `@colyseus/schema` декораторы `@type("number")`, `@type("boolean")`. Colyseus автоматически отправляет только изменённые байты.
2. **Троттлинг ввода:** Клиент буферизует ввод, сервер принимает максимум 20 команд/сек. Лишние игнорируются.
3. **Пулинг объектов:** Снаряды, взрывы, лут, тела умирающих → создаются через `Phaser.Physics.Arcade.Group` с `maxSize: 50`. Переиспользование вместо `new/destroy`.
4. **Рендер-отсечение:** `camera.setDeadzone()`, `sprite.setActive(false)` для объектов за пределами экрана.
5. **Лимит трафика:** ≤ 150 байт/тик/игрок. При 10 игроках × 20 Гц = ~30 КБ/с. Для слабой LAN (<10 Мбит/с) запас ×300.

## 5. РЕАЛИЗАЦИЯ МЕХАНИК (ПО КОНЦЕПТУ)

| Механика | Клиентская логика | Серверная логика |
|----------|-------------------|------------------|
| **Движение + Двойной прыжок** | `body.setVelocityX(moveSpeed * input.move)`, `body.setVelocityY(jumpForce)` при `input.jump` и `jumpsLeft > 0`. Ground check через `body.touching.down`. | Валидация частоты прыжков, проверка выхода за границы карты, relay позиции |
| **Присед + Подбор** | При `input.crouch`: `body.setSize(originalWidth*0.5, originalHeight)`, `sprite.setScaleY(0.7)`. Подбор: `overlap` с `WeaponPickup`, если `crouch && !pickupCooldown`. **Только 1 подбор за присед**. | Подтверждение `pickup` (cooldown 300ms), замена инвентаря, спавн `dropped_weapon` на позиции, обновление `player.weapon` в state |
| **Стрельба (клик)** | При `input.click && weapon.type !== 'fist'`: спавн `Projectile` по направлению курсора, анимация полёта (`velocity=800`), `overlap` с врагами. **Нет кулдауна, очередь только по кликам**. | Валидация `shoot` (≤10 Гц), расчёт урона при `overlap`, relay `HitEvent`, проверка дружественного огня (игнор) |
| **Взрывы / Откидывание** | При получении `EventPayload.type='explode'`: найти всех в `radius`, применить `force = (1 - dist/radius) * maxKnockback` к `body.velocity`. Анимация `explosion_01`. **Откидывает всех, урон только врагам**. | Рассылка события, валидация радиуса, нанесение урона только противникам, лог `environment_death` |
| **Зоны баз** | Рендер полупрозрачного оверлея `base_red`/`base_blue`. Если `player.x < baseRightX` и `team==blue` → таймер урона 5 HP/сек, моргание `alpha` + `tint`. **Зона по всей высоте**. | Отслеживание позиции, начисление урона в тик-лупе, лог смерти от среды, начисление очка противоположной команде |
| **Призрачный режим** | При `hp <= 0`: `body.setImmovable(true)`, `body.setAllowGravity(false)`, `sprite.setAlpha(0.4)`, `sprite.setData('ghost', true)`. Проход сквозь тайлы. | Блокировка `pickup`/`shoot`, запуск таймера 30с, авто-респавн по таймеру, relay `ghostTimer` |
| **Процедурная карта** | Получает `MapSeed`, строит тайлы локально через `MapBuilder`. Гарантирует проходимость: максимальный перепад ≤ `jumpHeight * 2`. Камера зумится до `zoom=1.8` для ограничения FOV. | Генерация seed (Mersenne Twister), рассылка `mapWidth/Height`, хранение спавн-точек оружия, валидация проходимости на этапе генерации |
| **Статистика / Победа** | Рендер HUD, таблица лидеров, подсветка своего игрока, чат-лента. | Хранение `kills`, `deaths`, `kdr` в памяти, расчёт командного счёта, отправка `StatsPacket` при `matchTime >= 600` |

## 8. WORKFLOW И ЗАПУСК (NPM 6 / NODE 12)

```bash

npm install

# Сборка shared модуля (обязательно первым шагом)

# Разработка (клиент на 5173, сервер на 3000)

npm run build

# Запуск сервера (раздаёт статику + поднимает WS)
npm start

# Проверка типов без компиляции
npm run typecheck
```

**Скрипты в `package.json`:**
```json
{
  "scripts": {
    "build:shared": "tsc -p shared/tsconfig.json",
    "dev:client": "vite --config client/vite.config.ts",
    "dev:server": "tsc-watch -p server/tsconfig.json --onSuccess \"node server/dist/index.js\"",
    "dev": "npm run build:shared && concurrently \"npm run dev:client\" \"npm run dev:server\"",
    "build": "npm run build:shared && vite build --config client/vite.config.ts && tsc -p server/tsconfig.json",
    "start": "node server/dist/index.js",
    "typecheck": "tsc --noEmit"
  }
}
```
**Требования к окружению:**  
- Node.js `12.22.12`  
- npm `6.14.16`  
- Браузер: Chrome 90+, Firefox 88+, Edge 90+ (WebGL2, `requestIdleCallback`)

## 📌 ПРИМЕЧАНИЯ ДЛЯ КОМАНДЫ
1. **Colyseus не заменяет игровую физику.** Он только синхронизирует состояние. Все расчёты траекторий, столкновений, knockback происходят на клиенте.
2. **JSON запрещён в продакшене.** Состояние идёт через `@colyseus/schema`, события через `msgpack-lite`. Любая отладка ведётся через логгер, а не через `JSON.stringify`.
3. **Валидация типов обеспечивается TypeScript.** Критичные игровые проверки (`kill`, `pickup`, границы, частота кликов) реализуются явными `if` в `GameRoom.onMessage`.
4. **Ассеты строго именуются.** Имена фиксируются в `shared/constants.ts`. Отклонение ломает загрузку и анимации.
5. **Оптимизация пакетов приоритетна.** Если размер пакета > 200 байт при 20 Гц → рефакторить структуру.
6. **Тестирование на слабом железе обязательно.** Целевой сервер: 2 ядра, 2 ГБ RAM. Клиент: i3, 4 ГБ RAM. Замер FPS и задержки сети проводится на каждом спринте.
7. **npm 6 не поддерживает workspaces.** Сборка `shared` выполняется явно перед запуском клиента/сервера. Импорт через относительные пути.
